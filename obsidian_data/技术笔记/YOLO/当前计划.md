改进点 A：针对“特征提取网络”的改进（解决任务2）
- **问题**：交通标志背景复杂，原始主干网络（Backbone）容易提取到无用背景。
- **方案**：引入**注意力机制 (Attention Mechanism)**。
- **具体术语**：
    - 建议在 Backbone 末端加入 **CBAM (Convolutional Block Attention Module)** 或 **CA (Coordinate Attention)** 模块。
    - **作用**：让模型“聚焦”于标志本身，抑制树木、建筑等背景干扰。
改进点 B：针对“多尺度与小目标”的改进（解决任务2）
- **问题**：摄像头拍摄时，远处的交通标志像素点极少，YOLO原始的下采样倍率（8倍、16倍、32倍）容易丢失小目标信息。
- **方案**：**增加小目标检测层 (Tiny Object Head)**。
- **具体术语**：
    - 保留原有的P3, P4, P5输出层，**增加一个 P2 层**（4倍下采样）。
    - **作用**：利用高分辨率的浅层特征图来检测微小的交通标志。
    - 备选方案：如果增加头部计算量太大，可以将下采样模块改为 **SPD-Conv (Space-to-Depth Convolution)**，这是2022-2023年非常火的针对低分辨率图像的技术。 
改进点 C：针对“复杂光照与遮挡”的改进（解决任务3）
- **方案**：**数据增强 (Data Augmentation)** 与 **损失函数改进**。
- **具体术语**：
    - 在训练阶段使用 **Mosaic-9**（9图拼接）或 **Mixup** 数据增强，模拟遮挡场景。
    - 针对光照不均，可以在预处理阶段引入 **MSRCR (带色彩恢复的多尺度视网膜增强算法)** 或简单的直方图均衡化（CLAHE）。
    - 损失函数可以将 CIoU 替换为 **WIoU (Wise-IoU)** 或 **SIoU**，这在2024-2025年的论文中很常见，能加快收敛。
方案：基于 **PyQt5** 开发桌面端检测系统。
- **功能规划**：
    - 支持图片/视频文件导入。
    - 支持调用本地摄像头进行实时检测。
    - 界面显示：原始画面、检测后画面、当前FPS、识别到的标志类别（如：限速60、禁止左转）。

核心创新点组合：
1. **特征提取（Backbone）**：引入 **CBAM** 或 **CA** 注意力机制。（解决背景干扰）
2. **特征融合（Neck）**：将原有的 PANet 结构改进为 **BiFPN**（加权双向特征金字塔）。（解决多尺度问题，这点比单纯加P2头显得更“结构化”，且BiFPN是经典涨点模块）。
3. **损失函数（Loss）**：引入 **WIoU (Wise-IoU)**。（解决低质量样本和收敛速度问题，比CIoU新）。
4. **工程系统**：**PyQt5 可视化界面**。（软件工程专业的“本命”任务）。

 

网络结构优化（Model Architecture Optimization）
- **引入 SimAM 无参注意力机制（Parameter-free Attention）：**  
    针对 CBAM 等传统注意力机制增加参数量的问题，在 Backbone 末端引入基于神经科学理论的 **SimAM** 模块。该模块能够在**不增加网络参数**的前提下，通过推导能量函数计算三维注意力权重，自适应地增强交通标志特征，抑制背景干扰，完美契合实时检测的需求。
- **构建 Slim-neck 轻量化特征融合网络：**  
    针对任务书要求的“实时检测”，采用 **GSConv (Ghost-Shuffle Convolution)** 替换 Neck 部分的标准卷积（Conv）及 C2f 模块。GSConv 结合了标准卷积的精度优势与深度可分离卷积的速度优势，配合 **VoV-GSCSP** 模块，在保持多尺度特征融合能力的同时，显著降低模型计算量（FLOPs），提升推理帧率（FPS）。
训练与优化策略（Training Strategy）
- **应用 WIoU 动态聚焦损失函数：**  
    引入 **WIoU (Wise-IoU) v3** 损失函数。利用其动态非单调聚焦机制，根据锚框的质量（离群度）动态分配梯度增益，解决交通标志在遮挡、模糊场景下的边界框回归难问题，加速模型收敛。
工程化系统实现（System Implementation）
- **基于 ONNX Runtime 的推理加速与系统开发：**  
    完成模型训练后，将 PyTorch 模型导出为通用的 **ONNX (Open Neural Network Exchange)** 格式。基于 **PyQt5** 开发可视化检测系统，底层推理引擎采用 **ONNX Runtime** 进行加速，以实现跨平台的高效部署和更低的推理延迟，满足智能交通系统的工程化标准。
